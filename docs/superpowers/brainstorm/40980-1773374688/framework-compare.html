技术栈对比：Next.js PWA vs React Native (Expo)

针对 AI 记账 App 场景的具体分析

⚡ Next.js + PWA

✅ 优势

  • Web + 移动一套代码，部署到 Vercel 极简
  • 与 Supabase JS SDK 无缝集成
  • SEO 友好，可被搜索引擎收录
  • 开发体验极佳，热更新即时生效
  • 无需上架 App Store，发布零门槛
  • Web API（摄像头、麦克风）基本够用

❌ 劣势

  • OCR/ASR 依赖浏览器 API，iOS Safari 限制较多
  • PWA 离线能力弱，后台任务受限
  • 无法访问原生相册深度功能
  • 用户体验有"网页感"，不如原生流畅
  • iOS 上 PWA 推送通知支持极差
  • 主屏图标需用户手动添加
📊 适合场景：预算有限、想快速验证产品、主要在 Android 或桌面端使用
📱 React Native (Expo)

✅ 优势

  • 原生摄像头 / 麦克风 API，OCR/ASR 体验更好
  • 真正的原生 UI 组件，手势流畅
  • 后台任务、推送通知完整支持
  • 可上架 App Store / Google Play，更正式
  • JS/TS 生态，Supabase 兼容良好
  • Expo 大幅降低原生开发门槛

❌ 劣势

  • 需要打包构建，发布周期较长
  • App Store 审核有被拒风险
  • 原生模块调试比 Web 复杂
  • 无法在桌面浏览器直接访问
  • 包体积较大（Expo Go 约 60MB+）
📊 适合场景：对拍照/语音体验要求高、想做正式产品、iOS 用户较多

🎯 关键决策点：OCR + ASR 体验

记账 App 的核心差异化在于拍票识别和语音输入。 PWA 的摄像头权限在 iOS 16+ 已支持，但调用原生 Vision / SpeechRecognition 框架需要 React Native。 若目标用户主要是 iPhone 用户，React Native 体验明显优于 PWA。 若主要是 Android + PC 混合用户，PWA 完全够用。

A

选 Next.js + PWA

快速上线，一套代码跑全平台

B

选 React Native (Expo)
