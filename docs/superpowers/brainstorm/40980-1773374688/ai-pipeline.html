AI Pipeline 设计

Section 3 / 4 — 三条录入通道的处理流程

📷 OCR 通道：拍照识票
① 拍照
Expo Camera
→
② 上传图片
Base64 → BFF
→
③ 腾讯云 OCR
票据/发票识别
→
④ GLM 提取
金额/商户/日期
→
⑤ 返回结构化数据
预填表单
→
⑥ 用户确认
写入 DB
GLM Prompt 示例：
从以下 OCR 文本中提取：金额、消费类别、商户名称、消费时间。以 JSON 格式返回。\nOCR文本：{ocr_text}
🎙️ ASR 通道：语音记账
① 按住录音
Expo AV
→
② 上传音频
WAV → BFF
→
③ 腾讯云 ASR
语音 → 文字
→
④ GLM 解析
"午饭花了35块"
→
⑤ 返回结构化数据
预填表单
→
⑥ 用户确认
写入 DB
GLM Prompt 示例：
从以下语音转文字内容中提取记账信息，返回 JSON：{amount, category, note, occurred_at}。\n当前时间：{now}。内容：{asr_text}
💬 自然语言查询通道
① 用户输入
"上周吃饭多少钱"
→
② GLM Text2SQL
生成 SQL
→
③ BFF 安全校验
只允许 SELECT
→
④ Supabase 查询
执行 SQL
→
⑤ GLM 汇总
生成自然语言答复
⚠️ 安全要点：BFF 对 GLM 生成的 SQL 做白名单校验（只允许 SELECT，禁止 DROP/UPDATE/INSERT），防止注入攻击。用户的 user_id 强制注入到 WHERE 条件，不依赖 GLM 生成。
🛡️ 统一降级策略：
  • 腾讯云 OCR 超时/失败 → 提示用户手动输入，不阻塞流程
  • GLM 解析失败 → 返回空预填表单，用户自行填写
  • NL 查询 SQL 校验不通过 → 返回"无法理解，请换个问法"
  • 所有 AI 调用设置 8s 超时，前端展示 loading 状态
