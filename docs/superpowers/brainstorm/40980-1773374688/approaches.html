架构方案选择

三种后端架构，核心差异在于 AI 编排逻辑放在哪里

A

Expo + Supabase Edge Functions 极简

所有后端逻辑（AI 调用、OCR、ASR）写在 Supabase Edge Functions (Deno) 里，一个平台搞定

✅ 优

  • 只需维护 Supabase 一个服务
  • 冷启动约 100ms，够快
  • 免费额度 500 万次/月

❌ 劣

  • Deno 生态与 Node.js 有差异
  • 腾讯云 SDK 需手动适配 Deno
  • 复杂 AI 流不易调试
B

Expo + Next.js API Routes (BFF) ⭐ 推荐

Next.js 作为 BFF（后端聚合层）部署在 Vercel，负责所有 AI 编排；Supabase 专注数据库和认证

✅ 优

  • TypeScript 全栈，Node.js 生态完整
  • 腾讯云/GLM SDK 直接 npm 安装
  • 未来想加 Web 端，直接复用 API
  • Vercel 免费部署，自动 CI/CD
  • Supabase 只做存储，职责清晰

❌ 劣

  • 两个平台（Vercel + Supabase）
  • Vercel Serverless 有 10s 超时限制
C

Expo + Hono 独立后端 最灵活

Hono.js 轻量 Node.js 后端部署在 Railway/自建服务器，完全控制；Supabase 只做数据库

✅ 优

  • 无超时限制，适合长流式 AI 输出
  • WebSocket 实时通信原生支持
  • 可部署国内服务器，访问国内 API 更稳定

❌ 劣

  • 需要自己运维服务器
  • Railway 免费额度有限
  • 初期开发成本最高
💡 我的推荐：方案 B
Next.js BFF + Supabase 是目前最主流的独立开发者（Indie Hacker）组合。Node.js 生态让腾讯云和 GLM 的 SDK 直接 npm 安装，开发体验最顺滑。Vercel 免费部署、自动域名，验证阶段零运营成本。未来想加 Web 端直接在同一个 Next.js 项目里加页面即可，迁移成本极低。
