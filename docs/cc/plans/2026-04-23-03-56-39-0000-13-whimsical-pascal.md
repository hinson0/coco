# 修复 backend 容器启动崩溃：keywords.json 路径解析失败

## Context（为什么要做）

`docker compose up` 时 backend 反复重启失败，所有 gunicorn worker 在 `from constants.keywords import ...` 这一刻爆掉：

```
File "/app/constants/keywords.py", line 12, in <module>
    Path(__file__).resolve().parents[3]
IndexError: 3
```

### 根因

`apps/backend/constants/keywords.py` 用 `Path(__file__).resolve().parents[3]` 上溯到 monorepo 根目录，再拼 `packages/shared/src/constants/keywords.json`，作为前后端共享关键词的"单一事实源"读取入口。

- **宿主机**：文件在 `<repo>/apps/backend/constants/keywords.py`，`parents` 链有 `constants → backend → apps → repo根`，`parents[3]` 命中 ✓
- **容器**：`apps/backend/Dockerfile` 的 build context 是 `./apps/backend`，整个 backend 被 `COPY . .` 到 `/app`。所以文件路径变成 `/app/constants/keywords.py`，`parents` 链只剩 `constants → /app → /`，`parents[3]` 越界 ✗
- **附带问题**：即便路径算对，容器镜像里也根本没有 `packages/shared/` 目录——它位于 build context 之外，COPY 不进来。

### 目标

让 backend 在容器和宿主机两种环境下都能正确加载 `keywords.json`，同时保持 `packages/shared/src/constants/keywords.json` 作为单一事实源不被复制（避免漂移）。

---

## 实施方案

### 改动 1：`apps/backend/constants/keywords.py` — 改用向上递归查找

替换硬编码的 `parents[3]`，改为从当前文件向上逐级查找 `packages/shared/src/constants/keywords.json`。这样 monorepo 重组、Dockerfile 改路径、未来移动文件都不会再爆。

```python
import json
from pathlib import Path

_REL = Path("packages/shared/src/constants/keywords.json")


def _find_keywords_json() -> Path:
    for parent in Path(__file__).resolve().parents:
        candidate = parent / _REL
        if candidate.is_file():
            return candidate
    raise FileNotFoundError(f"未找到 {_REL}（已向上检索至文件系统根）")


_data = json.loads(_find_keywords_json().read_text(encoding="utf-8"))

NOTIFICATION_INCOME_KEYWORDS: list[str] = _data["notification"]["income"]
NOTIFICATION_EXPENSE_KEYWORDS: list[str] = _data["notification"]["expense"]
SEMANTIC_INCOME_KEYWORDS: list[str] = _data["semantic"]["income"]
SEMANTIC_EXPENSE_KEYWORDS: list[str] = _data["semantic"]["expense"]
```

- 模块顶层文档 docstring 保留（说明 SSoT 来源）。
- 不引入 `os.getenv` 覆盖等过度配置——递归查找已足够通用。

### 改动 2：`docker-compose.yml` — 提升 build context 到仓库根

只有把 context 提升到仓库根，Dockerfile 才能 `COPY` 到 `packages/shared/`。

```yaml
backend:
  build:
    context: .
    dockerfile: ./apps/backend/Dockerfile
  restart: unless-stopped
  ports:
    - "8000:8000"
  env_file:
    - ./apps/backend/.env
  environment:
    DATABASE_URL: postgresql+asyncpg://coco:${POSTGRES_PASSWORD:-coco}@db:5432/coco
  depends_on:
    db:
      condition: service_healthy
```

`env_file` 路径相对 `docker-compose.yml`，原值 `./apps/backend/.env` 已正确，无需改动。

### 改动 3：`apps/backend/Dockerfile` — 调整 COPY 源路径，并复制 packages/shared

由于 build context 变了，所有 COPY 源路径需加 `apps/backend/` 前缀；同时把 `packages/shared/` 也复制到镜像里。

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.13-slim

ENV UV_INDEX_URL=https://mirrors.tencent.com/pypi/simple/

RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -i ${UV_INDEX_URL} uv

WORKDIR /app

# 依赖文件单独 COPY 以利用 layer 缓存
COPY apps/backend/pyproject.toml apps/backend/uv.lock ./

RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev --no-install-project

# 后端源码
COPY apps/backend/ /app/

# 共享 SSoT（关键词 JSON 等）。放到 /app/packages/... 后，
# /app/constants/keywords.py 向上递归一级即可命中 /app/packages/shared/...
COPY packages/shared/ /app/packages/shared/

RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev

COPY apps/backend/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh

EXPOSE 8000

ENTRYPOINT ["/entrypoint.sh"]
```

> 注：`COPY apps/backend/ /app/` 会再次写入依赖文件，但 layer 缓存命中时无成本，写两次比拆细规则更清晰。

### 改动 4：新建仓库根 `.dockerignore`

build context 从 `./apps/backend` 扩到仓库根，会把 `apps/mobile`、`node_modules`、`.git`、`docs/` 等大量无关内容塞进 build context，拖慢构建。需要在仓库根新建 `.dockerignore`：

```
# VCS / IDE
.git
.gitignore
.vscode
.idea
.claude
.cursor

# Python 缓存（沿用原 backend/.dockerignore）
**/__pycache__
**/*.pyc
**/*.pyo
**/.venv
**/.pytest_cache
**/.ruff_cache
**/.pyright
**/*.egg-info
**/dist
**/build

# 环境敏感
**/.env
**/.env.*

# 与 backend 镜像无关的应用
apps/mobile
apps/web

# Node 产物
**/node_modules
**/.expo
**/.next

# 文档与脚手架
docs
.remember
```

`apps/backend/.dockerignore` 可保留（更窄作用域），不影响。

```bash
# 预期：['收款', '到账', '转入']
```

### 2. Docker 构建并启动

```bash
docker compose build backend

```

### 3. HTTP 健康检查

```bash
curl -i http://localhost:8000/docs
# 预期：HTTP 200，FastAPI Swagger UI HTML
```

### 4. 关键词被正确加载（端到端）

调用任意走 `services/silicon.py` 关键词分类的接口（如 `/chat` 触发记账意图识别），确认通过 `SEMANTIC_INCOME_KEYWORDS / SEMANTIC_EXPENSE_KEYWORDS` 的分支不报错。

## 不做的事

- 不引入 `KEYWORDS_JSON_PATH` 环境变量覆盖——递归查找已覆盖所有当前与可预见场景，避免增加无价值的配置面。
- 不把 `keywords.json` 复制成 backend 内的 fixture——会引入双源漂移风险，违背 SSoT 设计意图。
- 不重写 entrypoint.sh、不动 alembic 配置——与本次 bug 无关。
